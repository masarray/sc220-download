SC220 MKII SUPPORT

Good diagnosis starts with complete evidence.

Use this page before opening an issue about SC220, SC220 MKII, SC220 Live, OBS, TikTok Live Studio, VB-CABLE, or a karaoke processor. The goal is to separate hardware, Windows, routing, software, and gain-staging problems.

PRIVACY & SECURITY

Do not upload sensitive data.

Remove license keys, activation IDs, personal email addresses, unnecessary serial numbers, credentials, and account information from screenshots or logs. Security vulnerabilities belong under SECURITY.md, not a public issue.

Checklist before declaring the device faulty.

Change one variable at a time. Record the result of every step so one change does not hide another.

1. Identity and connection

  • Photo of the model label: SC220, SC220 MKII, or another name.
  • Front and rear panel photos with port labels visible.
  • USB cable type and whether it supports data.
  • Direct USB port or hub/dock.
  • Source type: dynamic mic, condenser mic, guitar, mixer, or karaoke processor.
  • Complete wiring from source to headphones, speakers, and applications.

2. Windows and driver

  • Windows 10/11 edition, version, and OS build.
  • Device name in Device Manager and Windows Sound.
  • Visible input/output count.
  • Selected sample rate and bit depth.
  • Actual audio API or driver type: Windows audio, WASAPI, or ASIO when available.
  • Whether the device disappears after sleep, reconnect, or a port change.

3. Hardware controls

  • Input 1 and input 2 gain positions.
  • +48 V status and why it is enabled.
  • PAD and Line/Instrument status.
  • Whether the hardware meter moves.
  • Whether headphones/direct monitor produce sound.
  • Whether the problem remains with DSP and other applications closed.

4. Software and routing

  • SC220 Live, OBS, TikTok Live Studio, DAW, or other application versions.
  • Selected input, playback source, and stream output names.
  • Meter screenshots at every stage.
  • Whether the same source is captured twice.
  • Whether exclusive mode or another application is holding the device.
  • Whether the problem starts before or after GO LIVE/stream output.

A diagnostic order that avoids guessing.

Start with the simplest path and add one component only after the basic result is stable.

1

Hardware only

Test the microphone or source into the SC220 and listen through direct monitoring/headphones when available.

2

Windows input

Check the endpoint, Windows meter, sample rate, and microphone permissions.

3

One application

Use a single capture application without DSP, virtual cables, or extra monitoring.

4

SC220 Live

Add routing, faders, meters, and stream output only after the base input is proven.

5

Broadcast chain

Add OBS or TikTok, make a test recording, and compare meters with playback.

Common first-line diagnostic questions.

These are starting points. Control labels and driver support must still be checked against the physical unit.

The SC220 does not appear in Windows. What should I check?

Use a proven data cable, try a direct USB port, temporarily avoid hubs, check Device Manager and Windows Sound, then retest after a restart. Record whether it appears as an unknown device or not at all.

The microphone is only on the left or right.

A microphone connected to one input is a mono source. Select a mono channel or enable mono handling in the destination application.

A condenser microphone has no signal.

Confirm that the microphone requires phantom power, the XLR cable is correct, gain is not at minimum, and +48 V is enabled after the cable is connected. Phantom power is not a universal fix for every microphone.

The audio is echoed or doubled.

Disable either direct monitoring or software monitoring. Confirm that the source is not captured directly and again through SC220 Live or a virtual cable.

The audio clips even when the OBS fader is low.

Clipping is probably earlier in the chain. Lower source output or hardware gain, check PAD/line mode, disable extra processing, and inspect meters from input to output.

Should I install a driver from an unofficial website?

Not recommended. Do not install a driver binary that cannot be clearly tied to the vendor and model. Save screenshots of the device identity first and use an official source when one becomes available.
